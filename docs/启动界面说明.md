# 两秒启动动画与设置衔接

本次为 0.1.1 本地候选修订，不修改已发布的旧版。

## 正常启动

手动启动、已同意随包运行库条款且前台不处于全屏时，显示约 2 秒的启动卡片。
卡片正常结束后隐藏并清理自身，再打开普通可编辑的设置窗口。设置窗口接受
键盘和鼠标焦点；只有启动卡片和悬浮字幕不抢焦点。

程序不等待动画才初始化托盘和快捷键，也不因此加载 OCR 或翻译模型。
动画由 Qt 定时器驱动，不阻塞界面线程。Windows 减少动画设置开启时显示
同样约 2 秒的静态卡片，结束后仍打开设置。

## 不自动弹窗的情况

- 在动画期间框选、启停、清空、隐藏、操作托盘、手动打开设置或退出。
- 关闭启动动画，或以 `--background` / `--no-startup-animation` 启动。
- 登录自启使用带 `--background` 的新启动项；旧启动项需重新保存自启设置。
- 前台全屏或无法安全读取前台状态。自动打开设置前再次检查，期间切到全屏也跳过。
- 已有实例运行、翻译已运行、界面已关闭，或程序退出中。

动画清理与成功完成是两个独立信号：取消时只清理，不触发设置。
成功完成的设置操作只排队一次；排队之后发生上述操作仍能取消。
关闭设置回到托盘，不会再次打开，不会自动开启翻译。

在“设置”→“快捷键”中取消“手动启动时显示 2 秒启动动画，结束后打开设置”，
保存后，下次启动直接常驻托盘。

## 验证边界

源码测试覆盖自然结束、静态模式、提前关闭、重复信号、排队取消及程序退出；
专用 `--startup-self-test` 使用程序自己的 Qt 控件验证两秒计时与设置衔接。
离屏测试不读取用户屏幕、不注册全局快捷键，不证明实际桌面焦点、游戏全屏显示
或 NVIDIA 录制兼容。最终打包结果与测试记录以随候选包提供的说明为准。

本次不更换模型或录像兼容策略，也不宣称修复普通菜单错译和游戏独占全屏问题。
