# 2026-10-15 OCR 局部重识别说明

## 问题从哪里来

本轮使用程序专门绘制的 Windows 测试窗口，通过真实 MSS 抓屏和随包本地 OCR 复现问题，而不是只向翻译模型输入一段预先整理的文字。

观察到部分相邻文字检测框向外扩张后覆盖了同一个字形。分别识别各框，再直接拼接，就可能得到 `keep | P you`、`Use y | your`、`isa4 | 4-player` 等多余字符。这些错误会进入翻译模型，导致习语识别、数字或整句译文进一步出错。它与翻译模型本身的生硬表达是两个不同问题。

这不意味着所有孤立字母或重复数字都应该删除。真实的代词、冠词、数字和重复表达也可能恰好出现在框的接缝附近。

## 本轮处理方式

先检查已排序的同一文字行中的几何关系，再决定是否读取一个小范围的联合图像：

1. 相邻框必须近似水平、处于同一基线、具有足够的垂直重叠和相近高度。明显不同的文字行、缺失或无效坐标不会进入处理。
2. 重叠面积占较小框面积至少 20% 时，产生一次局部重识别候选；只沿紧邻框扩展到至少 8% 的较弱重叠，最多合并 3 个框。组内仍检查整体基线，避免逐框漂移到另一行。
3. 从原始物理像素图像裁出这些框的并集，增加少量边距。每帧最多 12 组，合并为一次本地识别器批量调用；只重新识别文字，不重新运行检测，也不重跑整行或整屏。
4. 联合图像的识别结果还必须通过保守的文本与置信度检查。识别器不可用、返回数量不符、结果不确定或保护检查失败时，都保留原结果。

这不是查找字符串后任意删除 `P`、`y` 或数字，也不是用正则把不顺眼的文字改成预期答案。没有像素重叠证据的内容不进入该路径；新识别结果也不能无条件覆盖旧结果。

## 安全保护与数据保留

本轮优先保护真实内容，已针对以下情况添加守卫及反例测试：

- 独立的 `I`、`a` 不能仅因与相邻字形相似而删除。
- 真实数字、否定词、问号等标点以及有意义的重复表达不能被吞掉；数字与字母形似本身不是删除依据。
- 多字母词的边界不能被随意拆分或连接，例如不能把 `therapist` 拆成 `the rapist`。
- 不合并独立消息，不对中文、路径、网址或代码式内容套用英文接缝修复。无法明确判断用途的孤立字符应保守处理，而不是猜测它一定是噪声。

原始 OCR 的每个 `TextLine`、框坐标和置信度均保留不变。通过检查的联合识别结果只改变供后续翻译使用的组装文本，不反写原始证据，也不改变选区和显示器坐标。

安全边界的最终实现与测试结果须以本轮最终验收报告为准，不能把当前说明当作所有候选情况都已修好的保证。

历史完整链路验收工具同时改为读取生产引擎的完整缓存身份，避免漏掉翻译输出策略标识而错误地等待超时。这不改变程序实际翻译行为，也不代表已执行该工具中的桌面输入或热键消息操作。

## 已知限制

- 保守回退会留下部分疑似 `c`、`1` 或标点错误。宁可暂时保留可疑字符，也不冒险删掉真实数字、代词或一句话的关键内容。
- 真实字体、字号、背景和文字运动会影响 OCR。联合识别并不总比原识别更好，因此必须有回退路径。
- 这轮没有替换或下载大型模型，未新增在线 OCR、付费翻译 API 或显卡运行组件。旧翻译模型的生硬表达、语义错译和部分漏译仍然存在。
- 自绘窗口的实际抓屏、局部图像重放和自动测试，不等于真实游戏、NVIDIA 同时录制、物理快捷键或悬浮字幕可见性的验收。本轮不能据此宣称这些场景已全部通过。
