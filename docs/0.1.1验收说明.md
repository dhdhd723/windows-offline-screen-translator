# 0.1.1 候选版验收说明

日期：2026-10-03。当前 pending，非已完成的测试报告，非全屏支持保证。
本轮用于检查快捷键和录屏兼容调整，不改写已发布 v0.1.0。

## 安全开始

完整解压本次 `ScreenTranslator-0.1.1-Windows-x64-candidate.zip`，不要用
Code → Download ZIP 或旧版 v0.1.0 运行包代替。保留 `_internal`、
`models`、`LICENSES`，退出旧翻译器后再启动新 exe。无需安装 Python。
首次阅读并明确接受运行库条款，拒绝时应退出，不开始捕获。

新配置默认 Ctrl+Alt+R 框选、Alt+T 启停、Alt+C 清空、Esc 隐藏/恢复。
升级保留旧配置的已保存键值：请进入托盘“设置”手动修改框选键，以托盘
显示为准；不自动覆盖个人快捷键。不能假定新按键在所有机器上无冲突。

“录屏兼容”默认开启（`recording_compatibility=true`）。开启时不对本
应用字幕施加 Windows 捕获排除，外部截图/录像/共享屏幕可记录字幕。
关闭才尝试排除字幕。把字幕放在选区外，防止自己的译文被再次识别。
默认兼容不保证每一种 NVIDIA 或其他录屏环境都已通过。

## 明早人工验收清单

每项记录“通过/失败/未测试”、实际版本和现象，不上传存档、个人画面
或原始诊断数据。若需要报告，只提供移除私人路径/内容的摘要。

1. **窗口文字基线**：普通窗口中的一两行英文与中文分别框选；能得到
   两方向译文，启停、清空、隐藏和托盘复制有效，字幕不抢输入焦点。
2. **星露谷窗口模式**：优先在游戏 Options → Graphics → Window Mode
   选 Windowed Borderless（无边框窗口）；它占满屏幕但仍是窗口模式。
   模式/分辨率/UI 缩放变化后重新框选同一对话区域。先确认捕获有画面、
   OCR 有原文、翻译有结果、字幕可见，分别定位“无译文”的环节。
3. **Fullscreen 对照**：与普通窗口及无边框比较；用户已反馈旧版全屏
   完全无译文。真独占全屏可能无法捕获或无法叠加字幕；失败时记录并
   改回无边框，不把一次初始化/合成图通过记成全屏支持。
4. **NVIDIA 对照**：不更改驱动、游戏或 DRM。观察翻译器空闲、框选、
   监控、字幕显示/隐藏、停止和退出各阶段的 NVIDIA 提示；保持外部
   设置一致，对比录屏兼容开/关。只调整本应用选项；待实测确定是否
   确有捕获保护冲突，不能预先宣称屏幕已不被占用。
5. **循环防护**：在兼容开启状态，先字幕与选区不重叠，再故意重叠；
   不应不断识别自己的字幕。重叠无法安全显示时应提示或隐藏，结果仍
   可从托盘复制。外部录屏可能包含字幕，这是默认兼容的正常边界。
6. **恢复和多屏**：真实拖选、Esc 取消；100%/150%/200% 缩放、第二屏
   和负坐标；Alt+Tab、模式切换后重新框选、反复启停、重启保留设置。
7. **连续运行**：同一环境运行至少 30 分钟、观察至少 50 次对话变化；
   稳定文字不反复 OCR/翻译，动态背景没有持续高占用，内存没有单向增长，
   停止/退出及时释放。更长时与干净 Windows 10/11 的测试另行补充。

目前 Steam 星露谷、NVIDIA 录屏以及上述物理输入/多屏验收未完成。
辅助工具初始化失败，没有绕过它操作游戏或注入输入。这里提供步骤，
不是已经执行过的结果，也不读取 Steam 存档、不注入 DLL 或修改驱动。

## 开发者出包门槛

- 源码与 Windows 版本资源一致为 0.1.1；源码/导出回归通过。
- 用固定纯 CPU 打包环境构建新 exe，实际自检报告版本必须为 0.1.1，
  新 exe/ZIP 哈希另行固定，不能拿旧 exe 配新源码来改名。
- 新目录 `--candidate` 导出，确认文件名与 manifest 的 source_version；
  版本读取只解析 TOML/AST，不运行待导出源码。旧 approved 不可沿用。
- 完整保留模型、原生库和原声明；32 个模型文件、字体、Microsoft
  原件映射、8 个对应源码归档必须重新检查，Qt 的 4 个档案实际随包。
- 新 ZIP 的 CRC、路径安全、隐私扫描、中文空格路径完整解压、自检、
  UI/托盘初始化与首次条款拒绝/缺失保护分别验证。
- 未取得游戏/录屏实机证据时明确列未测试；不改写 v0.1.0 标签/附件，
  不先公开正式 v0.1.1，再补测试。状态见 [发布状态](RELEASE_STATUS.md)。

## 依据与限制

星露谷官方 Wiki 说明 Windowed / Fullscreen / Windowed Borderless 三种
模式。[官方选项说明](https://wiki.stardewvalley.net/Options)

Microsoft 说明真独占由游戏控制显示，而无边框/全屏优化允许 DWM 合成
叠加层；普通置顶窗并不保证覆盖每一种全屏呈现路径。
[Windows 全屏说明](https://devblogs.microsoft.com/directx/demystifying-full-screen-optimizations/)

Windows 捕获排除只控制本应用自己的窗口，且依赖 DWM 合成；NVIDIA
指出检测到受保护应用内容时可能停止桌面录屏。它们支持做开关对照测试，
但不能单凭文档就确定用户机器的根因。
[Windows API](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)、
[NVIDIA 支持说明](https://nvidia.custhelp.com/app/answers/detail/a_id/5602)
