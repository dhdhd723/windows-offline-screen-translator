# 聊天修补候选说明

记录开始：2026-10-19；候选整理：2026-10-20。状态：本地候选，未发布到 GitHub，不覆盖旧版本。

## 这一轮实际改动

- 逐行对话模式使用 OCR 的物理位置判断有明确缩进的续行；两条带昵称的消息始终分开。缺少位置、位置与最终识别文字不符、同行左对齐等不确定情况，不擅自合并。
- 在明确选择的逐行模式中，保护 `Cool Guy`、`Other Player` 等两到三个首字母大写的英文显示名。昵称不送入翻译模型，也不参与中英方向判断。小写多词昵称、表情昵称和任意标题仍不能可靠判断。
- 关闭聊天词表时，逐行模式仍可分离昵称，但不偷偷展开缩写。无昵称的普通文字继续使用原来的缓存和整段模型调用。
- 两到五个已知的独立短回复可以组合处理，例如 `ty np lol` → `谢谢，没问题，哈哈`、`brb; cya` → `马上回来，再见`。含未知词、否定句、普通句子、自定义覆盖或代码等不会套用组合规则。
- 原文、翻译用文字和昵称分开保存；缓存包含消息处理策略，避免重用修改前的错误结果。停止、清空、切换设置及出现更新画面后，过期结果不得写入字幕或缓存。
- 增加仅使用生成图片的聊天自检，可检查实际 OCR、本地模型、昵称和短回复，不读用户屏幕。

不要求用户清除设置。已有场景预设保持兼容。测试阶段的增强模式配置仅保留兼容字段，当前候选不提供该模型入口，也不会加载或下载增强模型。

## 为什么这轮不直接换模型

对两种候选做过真实 Windows CPU 模型测试。更大的模型并不稳定优于现有模型：

| 私有试验 | 观察结果 | 处理 |
| --- | --- | --- |
| Hy-MT2 1.8B，Q4_K_M | 模型约 1.13 GB，曾出现把掩护承诺翻成否定句、把 clutch 理解成手包等错误 | 未纳入运行包 |
| Qwen3 4B Instruct 2507，Q4_K_M 社区转换 | 模型约 2.50 GB；本机无提示组单条中位约 3.11 秒，子进程工作集约 4.67 GB；仍有明显错义 | 未纳入运行包 |

这些是构造文本上的本机测量，不代表其他电脑或真实游戏表现，也不是准确率排名。候选继续使用原来的轻量模型、日语模型和已审查的运行依赖，不增加模型下载和常驻推理服务。研究代码、模型及原始报告留在私有目录，不混进普通用户运行包。

## 仍未解决

不能把这次改动称为“Roblox 翻译质量已全面解决”。实际文本检查仍见到 `rez` 指令遗漏、`1 hp` 错译为时间、`ill` 被理解为生病、出生点或 clutch 被按字面理解等问题。未知缩写即使没有被词表替换，模型仍可能自行猜错。讽刺、多人上下文、省略句、OCR 错字等也没有可靠保证。

继续改进需要把以下两类证据分开：先检查实际 OCR 是否与聊天原文一致，再检查模型是否理解正确。后续应使用脱敏的真实聊天原文与误译对照验收，不能只靠不断加入整句固定答案，或把程序能运行当作译义正确。

## 验收边界

当前验证包括单元/线程回归、生成图片上的实际 OCR、52 条构造文本的真实轻量模型对照，以及打包程序的隔离自检。52 条不是代表性样本或统计盲测，不给出“整体准确率”。最终 EXE 检查结果见随候选保存的验证报告；本文不预先声称打包成功。

冻结前完整源码回归为 4247 项通过、10 项跳过；跳过项不能算作通过。实际 OCR 图片检查为三组要求用例及一组小字诊断用例通过，素材均为程序生成，不是游戏截图。52 条文本对照中，7 条输出因短回复组合或昵称保护变化，其余 45 条与原版一致；这不代表其余译文都正确。原来的单独 `ty`、`np` 本来已能正确翻译，不能算成本轮新增成果。

未完成真实 Roblox 游戏、NVIDIA 录制、独占全屏及全新 Windows 机器验收。自动测试不操控游戏、不读取玩家私有聊天或截图、不注册全局快捷键，不把素材上传到外部服务。离线自检的 Python 连接拦截不等于操作系统防火墙审计。

完整运行目录中的 `ScreenTranslator.exe`、`_internal`、`models`、`LICENSES` 必须保留在一起。源码 ZIP 不是运行包。请先从托盘退出旧版，将候选完整解压到新目录，不要覆盖旧目录；若效果不合适，可退出候选后继续使用原版本。
