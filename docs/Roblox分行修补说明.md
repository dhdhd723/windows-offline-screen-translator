# Roblox 对话分行修补

本修补针对多条上下排列的对话被合并翻译的问题，不修改游戏抓屏、全屏显示或 NVIDIA 录制功能，也不代表这些兼容项目已经通过。

## 使用

从托盘打开“设置”，在“显示与翻译”的“文字排版”中选择“逐行对话（聊天／Roblox）”，保存后继续翻译。正在监控时切换模式会重新启动该区域的翻译任务，避免旧模式的结果迟到显示。

两条独立对话会按 OCR 识别出的上下行分段翻译，并保持译文顺序。若是一句话由于聊天框较窄自动折成两行，应选择“连续文本（段落／长句）”，保留句子上下文。当前不自动辨认聊天气泡、说话人或消息边界。

## 聊天缩写

“设置”→“聊天词表”默认启用缩写展开，只在逐行对话且英文 → 中文时使用。
内置 40 项，无需逐条添加；在“内置词表”分页可查看全部项，自定义词表可以留空。
例如按本词表约定将 `tys` 展开为 `thanks`、`np` 展开为 `no problem`，再交给离线模型；
原文与上下行边界保留，可识别的用户名、网址避开展开，未命中的词直接交给模型。
词义可能因社区而异，可用每行 `缩写 = 英文展开` 的自定义项覆盖内置词表。
自定义项最多 100 条，保存时严格校验；不支持空值删除内置项。
详细格式见[使用说明](使用说明.md#聊天缩写词表)。
新增词义与研究限制见[聊天内置词表](聊天内置词表.md)。

## 实现边界

- OCR 的行边界保留到翻译和字幕显示；连续文本模式仍忽略软折行。
- 去重、新鲜度检查与旧任务取消使用有序分行语义；相同文字但不同分行不再直接当作同一条结果。
- 缓存键加入排版模式和策略版本，不读取旧合并结果来满足逐行翻译。无需删除用户缓存或配置。
- 本轮仍按整个有序文本块缓存；新消息可能使多行一起重新翻译，尚未实现逐条增量缓存或逐行混合语言自动判向。
- 不增加 OCR／翻译模型或原生依赖，仍使用原本本地模型和 CPU 推理。

OCR 仍可能误识别单个字符；本修补保留识别内容，不把识别出的 `0` 强制改成标点。

本轮测试结果与 Windows 便携运行包另见交付目录的修补验收说明。自有窗口的测试不能替代特定 Roblox 游戏内实测。
