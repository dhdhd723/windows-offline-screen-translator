# 聊天缩写与昵称修订

2026-10-12 · 0.1.1 本地候选，不修改已公开旧版。

## 已定位的问题

旧实现默认连续文本，但词表只在逐行模式启用，因此默认设置下内置 40 项没有生效。
旧缩写测试只验证展开后的英文，没有验证最终中文。昵称保护也只阻止展开缩写，
没有阻止模型翻译昵称；带昵称的短消息还可能影响正文词义。

## 修订行为

- 英文 → 中文且词表开启时，两种排版都使用聊天策略，无需手动切换才能翻译 `ty`。
- 40 个内置缩写独立成消息时直接使用确定中文，例如 `ty` → `谢谢`、`np` → `没问题`。
  大小写及简单标点可识别，长句仍先英文展开再由本地模型翻译。
- 明确的短昵称冒号前缀原样保留，只把正文送入模型；两条有明确前缀的消息自动保留行。
  普通段落软换行仍按连续文本合并；无明确前缀的聊天可继续手动选逐行模式。
- `昵称: take lead` 采用聊天带头义，不把普通正文里的 `lead` 全部替换。
- 自定义英文规则仍优先，关闭聊天开关或中文 → 英文时不强制使用中文回复。
- 缓存包含新策略身份；清空、停止、设置改变和较新文字出现时仍执行原有取消检查。

## 限制与隐私

单独缩写也可能随社区和上下文改变含义，内置中文是本项目明确选择的聊天用法。
未知 `oms` 未经确认，不添加猜测释义；交给模型后仍可能误译。
普通口语、双关、非标准表达的语义质量没有因本次规则修改而整体解决。
