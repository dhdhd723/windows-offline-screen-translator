# 日语增强版交付与测试说明

日期：2026-10-16。Windows x64 本地候选，程序版本仍为 0.1.1。
本次发布标签为 `v0.1.1-japanese-20261016`，采用无损 7z 精简包；已发布的场景预设版、旧标签及附件均保留。

## 运行与设置

下载 `ScreenTranslator-0.1.1-Japanese-Windows-x64-lossless.7z`，从托盘退出旧版后，完整解压到新目录；系统无法打开时可使用 7-Zip。
进入 `ScreenTranslator` 文件夹运行 `ScreenTranslator.exe`，保留 `_internal`、`models`、`LICENSES` 及其他随包文件，不要只复制 exe。
完整包包含本地模型及运行依赖，无需另装 Python、配置显卡或使用付费 API。首次启动仍需阅读并确认随包运行库条款。

设置 →“显示与翻译”→“翻译方向”选择“日语 → 简体中文（需日语模型包）”，保存，再框选清晰横排文字并开启翻译。
新配置默认 Ctrl+Alt+R 框选、Alt+T 启停、Alt+C 清空并停止；旧配置保留原按键，以设置页为准。
连续文本用于一句自动折行，逐行用于两条独立消息。可将日语方向及其他设置保存成场景预设。

本轮只增加日语到简体中文。“自动判断中英方向”仍只处理中英；没有中文到日语、日语到英文或三语自动识别。
缺少日语模型时会明确提示，不会联网补模型。中文和英文原有模式保留，日文原文不做繁简转换；最终中文译文按既有策略转换一次简体字形。
切到日语时释放已加载的中英模型，切回中英时释放日语模型，均在推理线程执行；暂停和清空保留当前模型与缓存，方便恢复。
再次切换语言可能需要重新加载模型。包含日语预设的数据文件不应交给不支持日语的旧版编辑，旧版可能拒绝读取该预设文件。

## 测得的延迟与占用

同一台 Windows 机器、CPU 两线程、固定短句条件下，新 exe 首次日语翻译约 952 毫秒，后续 16 条短句中位数约 136 毫秒，范围约 113–192 毫秒。
这些仅为模型翻译耗时，不包括抓屏、文字稳定等待、识别间隔、OCR 或字幕显示，不能宣称端到端只需 136 毫秒。

独立源码离线测试进程加载 OCR 和日语模型后工作集约 672 MiB、峰值约 737 MiB；释放日语模型后约 149 MiB。
这是该测试进程的总工作集，不是 GUI 软件在所有机器上的固定占用，也不是单独模型增量。原始 ZIP 约 840 MB，本次无损 7z 约 791 MB；压缩不降低安装占用或运行内存。

## 已知翻译问题与未测范围

关键词检查通过不等于语义、语气和游戏措辞全部正确。真实模型仍有这些输出，未用测试专用替换表掩盖：

| 日文 | 实际译文 | 问题 |
| --- | --- | --- |
| ここで待ってください。 | 请等到这里。 | 应表达“请在这里等候”，当前有语义偏差 |
| ゲームを終了しますか？ | 你会结束游戏吗? | 游戏确认框更适合“是否退出游戏？”，当前生硬 |
| アイテムを3個集めてください。 | 请收集三个项目。 | 游戏语境下“物品”更自然 |

否定句“このドアを開けないでください。”在固定文本和合成图像中均得到“请不要打开这扇门。”；左右方向和数字的固定例通过，但不保证其他句子不会错译。
原中英模型的扩展语义关键词观察仍为 4/8，小写 l8r 的 OCR 混淆、长句重复或错译没有在本轮全部解决。

本轮没有完成真实日文游戏、Roblox 实时聊天、NVIDIA 录制、真独占全屏、物理混合 DPI 多屏或干净 Windows 系统的实机验收。
字幕链路验证使用程序自己的离屏 Qt 控件，捕获源是合成图像；没有读取用户桌面、注册真实全局快捷键或验证游戏内窗口层级/焦点。
竖排、注音小字、艺术字、动态逐字字幕、姓名/昵称及混杂语言不作为首版可靠支持范围。优先使用普通窗口或无边框窗口。
这仍是供试用的候选包，不是全面兼容或翻译准确率的证明，也没有代码签名。
