# 本地屏幕翻译器：聊天修补候选验收报告

日期：2026-10-20。候选标识：Chat-Core-Candidate-20261020。基础程序版本仍为 0.1.1，不能只凭版本号与以前的包区分，请看候选标识或文件校验值。

## 结论

已生成新的 Windows x64 EXE，并通过本机隔离自检。它是“聊天结构与短回复修补候选”，不是已经解决所有 Roblox 口语错译的正式升级，也没有更新 GitHub 发布附件。

本报告记录压缩前的运行候选验收。交付阶段还会单独检查压缩完整性、解压后的逐文件校验值和解压后的 EXE 聊天自检；该阶段未计入下面的源码测试数量。未通过交付检查的包不应提供给用户。

## 修补范围

- 独立带昵称消息保留边界；只有物理位置明确支持的缩进续行才合并。左对齐或位置不明时不猜测。
- 明确选择逐行模式时，部分两到三个英文词组成的显示名也能原样保留，不送入模型、不参与语言方向判断。
- 关闭词表不再同时关闭逐行昵称保护；无昵称的普通文字仍保留原缓存方式。
- 确认的独立短回复可以直接组合，例如 `Alice: ty np lol` → `Alice: 谢谢，没问题，哈哈`。这不适用于任意句子或未知缩写。
- 原文、模型输入和昵称分离；缓存包含处理策略；停止、清空、设置变化或出现新文字后，过期推理结果不显示、不写缓存。
- 新增生成图片上的聊天自检，不读取玩家屏幕或聊天记录。

原来的单独 `ty`、`np` 已经可以正确翻译，不能算成本轮新增修复。聊天仍使用原有轻量模型；两种试验性大模型未通过质量评估，其后端和权重没有加入运行包。为兼容已有配置，适配层和预设中保留了部分研究接口或字段，但正常程序只使用轻量后端，没有增强模型选择入口，也不会自动下载模型。

程序测试使用独立的新数据目录和仅含 Windows 系统路径的环境，不依赖 PATH 中的 Python；没有更改当前运行的旧版或其设置，也没有向桌面发送按键、注册全局快捷键、抓取用户屏幕或读取私有截图。报告没有记录连接尝试；自检拦截的是部分 Python TCP 接口，不等于对原生组件及操作系统全部网络行为的防火墙审计。

42 个模型文件、282 个运行依赖文件、125 个许可文件与原已审查运行包逐字节一致。本轮没有新增推理服务、第三方二进制或大语言模型。

## 明确未通过验收的部分

复杂 Roblox 口语仍未解决。构造文本实测中仍有 `rez` 指令丢失、`1 hp` 被错作时间、`ill` 被理解为生病、出生点和 clutch 按字面翻译、未知缩写被模型自行猜错等情况。自然程度、上下文理解和准确表达不能仅靠扩大词表保证。

两种更大离线模型在本机试验中也存在明显错义；其中一种资源开销和延迟明显增加。因此没有将它们作为已验收的升级装进候选包。

本次未完成真实 Roblox 游戏、NVIDIA 录制、独占全屏或全新 Windows 系统验收。不能宣称其他电脑和所有游戏均已成功运行。下一轮语义验收仍需脱敏的实际聊天原文、程序识别文字和错误译文三者对照。

## 使用与回退

1. 从托盘退出旧版；将完整候选包解压到一个新目录，不覆盖旧目录。
2. 打开 `ScreenTranslator` 文件夹，运行 `ScreenTranslator.exe`。无需安装 Python；首次正常启动仍须由用户阅读并选择是否接受随包运行库条款。
3. 请保留同目录的 `_internal`、`models`、`LICENSES` 和 `source`，不要只复制 EXE。源码 ZIP 不是运行包。
4. 游戏聊天建议明确选择逐行模式并保留词表开关，尽量框选清晰、少量文字。遇到歧义时，可关闭词表或设置自定义释义。
5. 若候选效果不合适，退出候选后继续使用旧版；旧程序没有被本次测试覆盖或删除。

更多边界说明见 `ScreenTranslator/source/docs/聊天候选说明.md`。
