# 日语 → 简体中文候选

本轮只增加日语到简体中文，不包含中文到日语、日语到英文或三语自动切换。
旧“自动判断中英方向”保持原行为，不会根据少量汉字或假名擅自改变用户原来的方向。
这是本地候选功能，不能把本文当成真实游戏或翻译质量已经验收的证明。

## 使用

1. 使用包含日语模型的完整增强运行包，完整解压，不要只复制 exe。
2. 设置 →“显示与翻译”→“翻译方向”选择“日语 → 简体中文（需日语模型包）”，保存。
3. 框选清晰横排文字，按启停键翻译。两条独立对话选择逐行；一句自动折行选择连续文本。
4. 可将方向及相关设置保存为“日文游戏”等场景预设。应用预设后仍须手动开启翻译。

已有中英模型包仍能使用中英模式。缺少日语模型时会给出增强完整包提示，不会联网下载或悄悄调用外部 API。
首次日语翻译需要加载并核验模型；模型较大，不保证与原有中英短句相同的延迟。
切到日语会在推理线程释放已加载的中英模型，切回中英会释放日语模型；缓存保留，但再次加载权重可能带来冷启动等待。
暂停/清空不卸载当前模型，以便恢复；切换语言和模型释放都不在 UI 线程执行。

## 本地识别与翻译

复用原 PP-OCRv5 mobile ONNX OCR 与其精确匹配字库。官方支持日文，字库包含平假名、片假名；是否能准确识别具体游戏字体仍要验证。
显式日语方向允许纯假名及汉字假名混排，不再因为没有汉字或英文字母而忽略纯假名文字。
不会在翻译前对日文汉字做 OpenCC 转换；OCR 原文和坐标保持原来的证据链。

翻译使用 `facebook/m2m100_418M` 原版权重，固定版本
`55c2e61bbf05dfb8d7abccdc3fae6fc8512fd636`，转换为 CTranslate2 INT8；只开放 `ja-zh`。
源语言标记固定日语，目标前缀固定中文，使用独立 SentencePiece 适配，不使用英文中转。
运行时没有新增 PyTorch、Transformers 或联网推理依赖；它们只在独立开发转换环境中使用。

最终日中译文仅做一次既有简体字形转换，和中英缓存分开。英文聊天缩写、游戏标题及英语习语规则不套用日文。
日文昵称暂不提供额外保名承诺；姓名、纯汉字同形词、专名和敬语可能被模型误译。

## 边界与测试

先检查配置、预设、纯假名入口、目标语言标记、取消与分块完整性、缓存隔离、工作线程和中英回归。
固定文本质量检查与“能返回中文”的功能检查单独计数，不用后者代替语义准确率。
自检使用固定横排合成图像和临时数据，不读取个人屏幕；`--self-test` 在模型清单包含日语时追加日语检查。
关键词检查只作粗略观察，不能证明每个词义、语气、否定或人名正确。

首轮不承诺竖排、注音小字、艺术字、动态逐字字幕、罗马字日语、多语言混杂聊天及所有游戏正确翻译。
也不改变现有真独占全屏、NVIDIA 录屏和物理多显示器验收边界。具体通过数、测得速度、失败例及文件哈希以本轮交付报告为准。

## 构建与来源

中英模型按原流程准备。日语模型在独立转换环境执行 `tools/prepare_japanese_model.py`，显式指定新的 models 目录和开发源权重缓存目录。
开发脚本先验证固定 SHA-256，再加载原始权重；保留模型卡、来源、量化说明及 MIT 文本。不要把开发环境的 DLL 或 wheel 复制进运行包。
新增模型文件必须加入 `models/manifest.json` 并完成新包整体核验；旧包原件不覆盖。

- [PP-OCRv5 官方语言范围](https://paddlepaddle.github.io/PaddleOCR/latest/en/version3.x/algorithm/PP-OCRv5/PP-OCRv5_multi_languages.html)
- [原始 M2M100 模型卡与权重](https://huggingface.co/facebook/m2m100_418M/tree/55c2e61bbf05dfb8d7abccdc3fae6fc8512fd636)
- [CTranslate2 M2M100 适配说明](https://opennmt.net/CTranslate2/guides/transformers.html#m2m-100)

应用自身许可状态不因增加模型改变；第三方模型和运行库保持各自许可。完整许可材料位于随包 LICENSES 及模型目录。
